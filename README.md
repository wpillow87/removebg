# 图片去背景工具（本地 CPU 运行）

批量去除图片背景、只保留主体，再把成品整理成一个素材库。全程本地计算，不联网（只有首次下载模型时需要联网）。

---

## 程序在做的两件事

1. **消除背景**：`rembg` + ONNX 模型推断蒙版，把背景变成透明。
2. **按主体裁剪（清理空白）**：按非透明像素的最小外接矩形，把主体四周的空白裁掉，只留主体。
   去完背景经常会剩一大片空白，这一步就是把它收紧；界面上「裁剪边距」（默认 2px）控制外扩多少。

第 2 步不只在处理流程里跑：素材库有独立的 `清理空白` 按钮，而且**每次旋转之后都会自动跑一次**（旋转会在四角带出新的空白）。

界面上分成两个顶层标签页：

| 标签页               | 干什么                                                  |
| -------------------- | ------------------------------------------------------- |
| **处理**       | 加图 → 抠图 → （可选）手动引导 / 转正 → 保存到素材库 |
| **我的素材库** | 浏览、排序、分组、改名、清理、压缩、导出成 PNG / ICO    |

---

## 功能一览

**处理页（抠图）**

- 抠图：`rembg` + ONNX 模型，纯 CPU 推理，可选三个模型
- 自动裁剪：按主体外接矩形裁剪，去掉四周空白，保持长宽比
- 多主体处理：一张图有多个物体时可只保留面积最大的那个
- 批量：支持文件 / 文件夹（也可直接拖进窗口），串行处理 + 进度条，随时可取消
- 对比预览：左右并排显示「原图」与「去背景结果」
- 手动引导：在画布上画绿框（要的）/ 红框（不要的）修正蒙版，可撤销、可二次迭代
- 旋转：90° 大调 + 1° 微调 + 滑杆，转完自动清理空白
- 两个出口（都按各自的旋转角度转正后再输出）：
  - `以 webp 格式保存到 gallery`：入库，统一「长边 ≤ 800px + 无损 WebP」，存完自动清空列表
  - `导出 PNG 到桌面`：只往桌面丢一份原尺寸透明底 PNG，**不进素材库**、也不清空列表

**我的素材库**

- 卡片 / 列表两种浏览模式，列表模式右侧带预览面板
- 排序：添加时间 / 名称 / 大小；分组：按文件名里的 `[标签]`
- 图片尺寸三档（40 / 100 / 160 px），可隐藏文件名与标签
- `重命名 & 分组`（F2 或双击）：改真实文件名、打标签、单选还能顺手转正；重名自动加 `_1`
- `清理空白`：手动按主体裁掉四周空白
- `压缩`：长边压到 800 + 无损 WebP，非 WebP 的转成 `.webp`
- `导出所选`：透明底 PNG、ICO 图标（多尺寸，居中或按内容铺满）

**支持的输入格式**

`jpg` / `jpeg` / `png` / `webp` / `bmp` / `heic` / `heif` / `svg`（矢量图自动光栅化）

## 模型

模型文件（加起来约 1.3GB）**不进仓库**，都放在 `models/` 目录下，程序用环境变量 `U2NET_HOME`
指向它（启动时写入），运行时只读本地文件：

| 文件                     | 适用场景                           | 体积      |
| ------------------------ | ---------------------------------- | --------- |
| `isnet-general-use.onnx` | 通用：电子元件、产品、杂物、动物等 | 约 170 MB |
| `u2net_human_seg.onnx`   | 人像：人物半身 / 全身              | 约 168 MB |
| `bria-rmbg.onnx`         | RMBG-2.0：效果最好、速度最慢       | 约 977 MB |

### 缺失时自动下载

模型文件不在时**不用手动准备**，两条路都会自动触发下载：

| 触发时机                     | 表现                                                          |
| ---------------------------- | ------------------------------------------------------------- |
| 在「处理参数」里**选中**该模型 | 立刻开始下载，入口是模型状态文字（`正在下载 …：42%（72/168 MB）`） |
| 直接点 `开始处理`            | 先下模型再处理，进度走状态栏 / 进度条                         |

- 下载地址与校验值（md5 / sha256）都取自 rembg 自带的 session 定义，程序不另维护一份 URL。
- 下载走 pooch，**下完会自动校验**；校验不过会重来，不会留下半个文件。
- 状态文字右边有个 `下载（约 168MB）` 按钮，是给「自动下载失败后重试」用的。
- 下完之后就永久离线可用，换电脑把整个文件夹（含 `models/`）拷过去也行。

万一网络实在下不动，可以手动下载后放进 `models/`（注意把文件名改成上表里的名字）：

- 通用 / 人像：`https://github.com/danielgatis/rembg/releases/download/v0.0.0/<文件名>`
- RMBG-2.0：`https://github.com/danielgatis/rembg/releases/download/v0.0.0/bria-rmbg-2.0.onnx`
  （release 上是 `bria-rmbg-2.0.onnx`，放进来要改名成 `bria-rmbg.onnx`；不改也行，启动时会自动改名）

### 为什么三个模型是平铺的

rembg 新版往 `models/models/<模型名>/<模型名>.onnx` 写（每个模型一个子目录），
它的 `BaseSession.resolve_existing()` 又**同时兼容老的扁平布局**：

```python
candidates = [
    os.path.join(cls.model_dir(...), fname),    # ① <home>/models/<名字>/<名字>.onnx  ← 新版规范位置
    os.path.join(cls.legacy_home(...), fname),  # ② <home>/<名字>.onnx               ← 老的扁平位置
]
```

本项目统一用**扁平布局**（②），三个模型直接放在 `models/` 下：

- **读取**用 `remover.existing_model_path()`，①② 两条路径都查，所以文件位置不整齐也能用。
- **归位**用 `remover.normalize_model_layout()`（每次启动、每次下载完成后各跑一次）：
  把 ① 里的文件、以及沿用 release 原始名的 `bria-rmbg-2.0.onnx`，都搬到
  `models/<模型名>.onnx`，顺手清掉空的 `models/models/`。
  搬不动（文件被 onnxruntime 占用）也不影响使用，启动时会再试一次。

## 使用说明

### 处理一张（批）图

1. `添加图片` / `添加文件夹`，或把文件、文件夹直接拖进窗口
2. 选择模型（电子元件 / 产品选「通用模型」，人像选「人像模型」）；
   这个模型还没下载过的话，此刻会自动开始下载（状态文字上有进度）
3. 需要时调整：裁剪边距（默认 2px）、是否只保留最大主体
4. 点击 `开始处理`，处理中可 `取消`
5. 在左侧列表点选任意图片查看前后对比
6. 需要时点 `修改` 进手动引导，在画布上画绿框（要的）/ 红框（不要的），可 `撤销`、`完成`
7. 方向不对就用 `旋转` 条转正（只作用于右边的处理结果，转完自动清掉新带出来的空白）
8. 选一个出口：
   - 点 `以 webp 格式保存到 gallery`，结果按「长边 ≤ 800px + 无损 WebP」写入 `gallery/`，**处理列表随即清空**，可以直接开始下一批
   - 点 `导出 PNG 到桌面`，原尺寸透明底 PNG 直接落到桌面，**不进素材库、列表也不动**，可以继续调角度再入库

> 处理页不做导出格式设置。ICO 等其它格式统一在「我的素材库」里按需导出。

### 处理参数

| 参数           | 说明                                                        |
| -------------- | ----------------------------------------------------------- |
| 模型           | 通用 / 人像 / RMBG-2.0 三选一，右侧显示是否已就绪和体积     |
| 裁剪边距       | 主体外扩容的透明边距，防止软边缘被切掉。默认 2px，可 0~20px |
| 只保留最大主体 | 多个物体时只保留连通面积最大的那个，其余变透明              |
| 边缘去色晕     | 去除软边缘残留的原始背景颜色（更慢，默认关闭）              |
| 清理蒙版噪点   | 形态学开运算 + 高斯平滑，去除蒙版小噪点，可能损失极细结构   |

## 旋转

处理结果正下方是一条旋转控件，**只作用于「处理后」的结果图**（左边原图始终保持原始方向），保存到素材库时用的就是旋转后的图：

| 控件                      | 作用                                                  |
| ------------------------- | ----------------------------------------------------- |
| `↺ 90°` / `↻ 90°` | 逆时针 / 顺时针整转 90°，找正方向用                  |
| `− 1°` / `+ 1°`    | 每次 1° 微调，**长按可连续**微调               |
| 中间的角度框              | 显示当前角度（正数 = 顺时针），也可以直接输入精确角度 |
| 滑杆                      | 左右拖动找正，一格 1°                                |
| `归零`                  | 恢复成原始方向                                        |

- 90° 的整数倍走 PIL 快速路径，不会有画质损失；其它角度用双三次插值，四个补出来的透明角**会在旋转后自动裁掉**。
- 调角度的过程里画布保持未裁状态（免得每按 1° 就跳一下，看不清转正没有），**停下来 / 保存时**才收紧。
- 处理页的预览做了 120ms 防抖：长按 `−/+` 时角度先记住，停手后再重绘那张大图（大图转一次要 200ms 上下）。
- 旋转是每张图独立记录的，切换图片会各自记住自己的角度，重新处理也不会丢。
- 结果图被旋转后，**在结果图上画框会被禁用**（画框坐标和未旋转的结果图对不上）。要画框就先 `归零`，或者改在左边的原图上画。

## 压缩与尺寸

素材出口统一是「**长边 ≤ 800px + 无损 WebP**」：

- **只缩不放**：长边超过 800 才按比例缩下来，本来就小的一个像素都不动，长宽比永远不变。
- **无损 WebP**：保留透明通道和软边，比同尺寸 PNG 小一截；`method=6` 是最高压缩档。
- **不发黑边**：缩小之前先把 RGB 预乘 alpha，缩完再反预乘。透明区域的 RGB 本来就是 0，
  不预乘的话会和主体边缘平均到一起、缩出一圈黑边。
  （顺带一提：Pillow 12 的 `resize` 内部也会预乘，两条路结果一致；代码里显式做是为了防老版本 Pillow。）

两个入口：

| 入口                             | 行为                                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------- |
| `以 webp 格式保存到 gallery`（处理页） | 自动：转正 → 清空白 → 缩到 800 → 存无损 WebP                                        |
| 素材库`压缩` 按钮                | 手动：对选中的素材做同样的事；非 WebP 的转成`.webp`（同名自动加 `_1`，原文件删除） |

> 处理页的 `导出 PNG 到桌面` 不走这条路：它是原尺寸透明底 PNG，只落到桌面、不进 `gallery/`。

> `压缩` 是**原地覆盖**，缩了就回不去；已经是 WebP 且尺寸合格的会就地重写。
> 另外 JPEG 这类本来就是有损的照片，转成无损 WebP 未必更小 —— 但缩到 800 之后，
> 总体上几乎一定比原文件小。

## 我的素材库

用来管理保存在 `gallery/` 里的成品。

### 浏览与排版

| 控件                | 说明                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------- |
| `卡片` / `列表` | 两种浏览模式                                                                                         |
| 右侧预览面板        | **只有列表模式有**，约占界面 1/8、位于右上角，下方显示文件名、分组、尺寸、大小、添加与修改时间 |
| `排序`            | 添加时间（新→旧，默认）/（旧→新）/ 名称 / 大小                                                     |
| `分组`            | 不分组 / 按标签分组。一个文件有多个标签时会**同时出现在每个分组里**                            |
| 图片尺寸            | `40 px` / `100 px` / `160 px` 三档单选，默认 100，卡片封面和列表缩略图共用                     |
| 显示文件名及标签    | 复选框，默认勾选；取消后只留图片，卡片和列表行会自动收紧                                             |
| 间距                | 固定 0（密集排布）                                                                                   |

### 工具栏

| 按钮                   | 说明                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| `刷新列表`           | 重新扫描`gallery/`                                                 |
| `添加图片`           | 把外部图片复制进素材库                                               |
| `重命名 & 分组 (F2)` | 改文件名 / 打标签 / 单选转正，详见下一节                             |
| `清理空白`           | 把选中素材四周的透明空白裁掉，只留主体，直接覆盖保存（多选会先确认） |
| `压缩`               | 把选中素材压成「长边 ≤ 800px + 无损 WebP」，非 WebP 的转成`.webp` |
| `删除选中`           | 从磁盘删除（有确认框）                                               |
| `打开目录`           | 用资源管理器打开`gallery/`                                         |

底部还有一条 `导出所选`：勾选 PNG / ICO、ICO 尺寸、ICO 定位方式（居中 / 按 PNG 内容铺满）、
选择输出目录，然后导出。

快捷键：列表里按 `F2` 重命名 & 分组、按 `Delete` 删除（只在本页面有焦点时生效，不会打扰处理页）。

> 旋转和清理空白都是**原地覆盖保存**，所以只有 **png / webp**（保留透明）和 **jpg / jpeg**（垫白底）
> 能做；svg（会丢矢量）、ico（多尺寸包）、bmp / heic 会被跳过并提示。
> 改过内容的文件会靠 `mtime + 大小` 让缩略图缓存自动失效，界面上立刻能看到新图。

### 重命名 & 分组对话框

双击素材（或按 `F2`）打开，左栏是文件名和标签，右栏是预览和旋转：

| 栏 | 内容                                                                                     |
| -- | ---------------------------------------------------------------------------------------- |
| 左 | 文件名（默认已全选，直接敲键盘就能改）+ 后缀、常用标签 chips、新标签输入、最终文件名预览 |
| 右 | 棋盘格透明底预览 + 旋转控件（`↺/↻ 90°`、`−/+ 1°`、角度框、滑杆、`归零`）      |

- **单选**：可改主名，标签可增可删；角度不为 0 时点「确定」会把文件**转正 + 清理空白后覆盖保存**（文件名、扩展名不变）。
- **多选**：文件名框**也可以改** —— 留空就各自保持原名（只追加标签），填了就统一改成这个名字；
  旋转不开放（避免一次转错一整批）。
- 能原地旋转保存的格式：**png / webp**（保留透明）、**jpg / jpeg**（垫白底）。
  SVG 会丢矢量、ICO 是多尺寸包、BMP / HEIC 写入不稳，这几种在对话框里会提示不支持，需要先导出成 PNG。

**重名自动加序号**：目标名字被占用时，会在**主名**后面自动加 `_1` / `_2`，
序号始终排在标签前面，所以标签规则不会被破坏：

| 想要的名字                 | 实际情况                          | 最终结果                               |
| -------------------------- | --------------------------------- | -------------------------------------- |
| `led灯`                  | 磁盘上已有`led灯.png`           | `led灯_1.png`                        |
| `led灯[电子设备]`        | 磁盘上已有`led灯[电子设备].png` | `led灯_1[电子设备].png`              |
| `灯`（3 个文件统一命名） | 本批里互相撞名                    | `灯.png`、`灯_1.png`、`灯_2.png` |

留空不变的名字不会被当成改动；计划好的最终名字保证互不冲突，也不会覆盖任何现有文件。

### 标签与分组

标签直接写在文件名末尾，换电脑、拷文件夹都不会丢，不需要额外的数据库：

```
led灯[电子设备][我的物品].webp
└─ 名字 ─┘└── 标签1 ──┘└── 标签2 ──┘
```

- 界面上只显示名字 `led灯`，标签单独作为「分组」展示
- 按标签分组时，`led灯` 会同时出现在「电子设备」和「我的物品」两个组里；没有标签的归入「未分组」
- 写文件时统一用半角 `[ ]`，读取时半角 `[ ]` 和全角 `【 】` 都认
- 常用标签存在 `tags.json`，在「重命名 & 分组」里勾选「把上面勾选的新标签存为常用标签」即可累积

### ICO 图标

- **居中**：以图片为中心取一个包含整图的正方形，四周多余区域为透明
- **按 PNG 内容铺满**：先按透明像素裁到实际内容，再补成正方形，图标视觉上更大

## 上传到自己的 GitHub

模型（1.3GB）、素材库、日志都已经在 `.gitignore` 里，仓库里只会是源码：

```powershell
git init
git add .
git status --short          # 先确认列表里没有 models/ gallery/ logs/ tags.json .venv/
git commit -m "图片去背景工具：抠图 + 素材库"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

别人克隆之后直接按「运行」那三步装依赖、启动即可，模型会在使用时自动下载。

## 启动故障排查

双击 `启动工具.bat` 没反应、或弹出 Qt 报错时：

1. 启动脚本会等最多 15 秒确认界面是否真的创建成功；失败时自动用记事本打开 `logs\startup.log`。
2. `logs\startup.log` 按时间记录启动到了哪一步（Python 路径、Qt 插件目录、`QApplication` 是否创建成功、界面是否就绪），能直接看出卡在哪。
3. 想在命令行看到实时报错：`.\.venv\Scripts\python.exe run.py`

踩过并修好的几个坑：

- **程序路径含中文**：Qt5 会把非 ASCII 目录解析成 `????`，导致 `no Qt platform plugin could be initialized` 崩溃（退出码 `0xC0000409`）。
  `app/paths.py` 的 `fix_qt_plugin_path()` 已在创建 `QApplication` 之前用 `QCoreApplication.addLibraryPath()` 修正，**不需要改目录名**。
- **onnxruntime 与 PyQt5 的原生 DLL 冲突**：`fix_qt_plugin_path()` 会先把 `onnxruntime` 导入进来再加载 Qt，避免同名的 OpenMP / VC++ 运行时 DLL 互相覆盖导致段错误。
- **`.bat` 必须是 CRLF 换行**：LF 换行会让 cmd 解析带括号的 `if` 语句块时错位，脚本会静默失效（`start` 那行根本不执行）。
  修改 `启动工具.bat` 后请确认换行符是 CRLF、编码为 GBK。
- **关窗时后台线程没收干净会导致进程 abort**（同样是退出码 `0xC0000409`）：处理线程和素材库的缩略图线程都会在 `MainWindow.closeEvent` 里 `cancel + wait`，别去掉这段。

## 后续打包 exe（现在不做）

- 建议用 `--onedir`（单文件模式启动慢、体积大）
- 需要一起打包：`onnxruntime` 的 DLL、PyQt5 插件（含 QtSvg）
- `models/` 可以不打包：exe 同级目录没有模型文件时，程序会自动下载到 exe 同级的 `models/`；
  想做成完全离线版，就把 `models/`（1.3GB）一起压进去
- 模型文件、素材库目录（`gallery/`）、`tags.json` 都按「程序目录」解析，打包后依然指向 exe 同级目录
